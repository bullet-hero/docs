# gv 0.13.3

スマートフォンでのメモリ処理（元に戻す履歴の上限、メモリ不足警告への対応、リークの修正）と、プレハブモードの2つの修正

- エディターの新しい設定`履歴オブジェクト数`は、元に戻す履歴がステップ数とは別に保持するオブジェクトの数を制限します。1回の大量削除は1ステップですが、50,000個のオブジェクトを含むことがあり、この上限はまさにそれを抑えます。デフォルトではスマートフォンは200,000個まで保持し、デスクトップには上限がありません。`0`で上限がなくなります
- AndroidやiOSがメモリ不足を警告すると、ゲームが対応するようになりました。エディターはもう到達できない履歴のブランチを破棄し、ゲームはどこからも使われなくなったものを解放します。以前は警告を誰も受け取らず、結果はシステムによるゲームの終了だけでした
- レベルを開くたびに、テクスチャ1つにつき2つのマテリアルがセッションの終わりまでメモリに残っていました。現在はレベルを閉じるときに解放されます
- エディターでレベルを閉じると、レベルのデータが解放されます。以前は次のレベルを開くまでメモリに残っていました
- 重いレベルのあと、そのために確保したメモリが通常のレベルに必要な量の4倍を超え、次のレベルで不要な場合、ゲームはそのメモリを返します
- プレハブタイムラインは、プレハブモードでの編集のたびに一番上の行へ跳ばなくなりました。リセットされるのは、プレハブモードに入ったときだけです
- プレハブテンプレート内で親が設定されていない最上位のオブジェクトは、レベル内のコピーと同じように、テンプレートのタイムラインに合わせられ、そのアンカーに従うようになりました。以前は貼り付けによってテンプレートの外に残ることがあり、エディターでの表示と実際の再生が異なっていました
