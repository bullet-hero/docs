# プレハブモード

プレハブモードではテンプレートを編集し、保存するとその編集がテンプレートのすべての配置に反映されます。配置のインスペクターにある「プレハブを編集」ボタンで入り、Ctrl+Shift+Eでレベルに戻ります

## プレハブモード

> [!caution] 注意
> 編集しているのはテンプレートであり、その配置の1つではありません。保存すると、このテンプレートを参照するすべての配置に変更が反映されます

配置の仕組み：
- 配置をテンプレートに向けた時点で、配置はテンプレートのオブジェクトの実際のコピーを、永続的なIDとともに受け取ります。エディターの中では、プレハブの子はまったくふつうのオブジェクトです
- レベルファイルには配置だけが保存されます：テンプレート、コピーのID、オーバーライド。コピーはレベルを読み込むたびにテンプレートから作り直されます
- 配置は**インスタンスごとのオーバーライド**でテンプレートと違う状態にできます。オーバーライドは、そのようなオブジェクトをプレハブモードの**外で**編集したときに記録されます
- プレハブモードで行った編集はオーバーライドを記録しません。テンプレートそのものを変更します

> [!tip] ヒント
> テンプレートは重ねて開けます。テンプレート内の配置は自分のテンプレートを開き、`{{ui:editor_prefab-timeline_close}}`で元に戻ります。同じテンプレートを同時に2回開くことはできません。入れ子の上限は8階層です

詳細：[[2_reuse]]

## 入り方と出方

入る方法は2つあります：
- 配置のインスペクターにある`{{ui:editor_inspector-prefab_edit}}`
- レベル設定の`プレハブ`タブで、テンプレートの行にある`{{ui:editor_level-prefab-item_edit}}`。配置を必要としないので、どこにも配置されていないテンプレートや、別のテンプレートの中にしか配置されていないテンプレートも開けます

コンテキストメニューとコマンドパレットにある`{{ui:editor_context-menu_open-prefab}}`は、選択中の配置、または配置が持ち込んだオブジェクトに対して同じことをします。テンプレート内の対応するオブジェクトがすぐに選択されます

出る方法も2つあります：
- プレハブタイムラインの`{{ui:editor_prefab-timeline_close}}`は1階層だけ出て、このテンプレートを開いたテンプレートに戻ります
- メインツールバーのステータス（`「...」を編集中`）と`Ctrl+Shift+E`は、開いているすべてのテンプレートを一度に出て、レベルに戻ります

入るたび、出るたびに選択は解除されます。1階層戻ると、そのテンプレートで選択していたものが復元されます

テンプレートの中でも、選択はレベルと同じように動きます：クリック、`Ctrl`+クリック、矩形選択、削除、コピー、折りたたみ。ビューポートでのクリックは何も選択しません：ビューポートはレベルを表示し続け、そこにテンプレートのライブプレビューはありません

## テンプレートの中

テンプレートのすべてのオブジェクトは、その**ルート**の下にぶら下がっています。ルートは：
- テンプレート全体にわたります。その長さは`{{ui:editor_prefab-mode-frame_length}}`で、ルートのインスペクターと`プレハブ`タブで同じ数値です
- 削除することも、親を設定することもできません
- `{{ui:field_common_active}}`と`{{ui:editor_inspector_layer}}`は読み取り専用です。これらは各配置のものです

ちょうど1つのオブジェクト（ルートを含む）が選択されているとき、新しいオブジェクトはその下に入ります。それ以外のときは、テンプレートの最上位、つまりルートの下に入ります。新しいオブジェクトは親の期間全体にわたり、両端がアンカーされます。最上位ではそれがテンプレート全体です

レベル全体を必要とするジェネレーターはここでは使えません。選択からプレハブを作成することと、配置のフラット化も、テンプレートの中では拒否されます

## 選択からプレハブを作成

選択したオブジェクトを新しいテンプレートに変え、それらがあった場所にそのテンプレートの配置を1つ置きます。その後もレベルの見た目とプレイは変わりません

場所：
- ヒエラルキーの行のメニューにある`{{ui:editor_context-menu_pack-prefab}}`
- ビューポートのコンテキストメニュー
- コマンドパレットの`{{ui:cmd_editor_pack-prefab}}`、`Ctrl+G`
- レベル設定の`プレハブ`タブにある`{{ui:settings_level-settings_resources-prefabs-pack}}`

確認は求められず、元に戻す操作1回分です。新しい配置が選択された状態になります。オブジェクトが1つならテンプレートにはその名前が付きます。複数なら`Prefab`という名前のテンプレートになります。名前はレベル設定の`プレハブ`タブで変更できます

拒否されるもの：
- 配置、または配置が持ち込んだオブジェクト。これらにはメニューが代わりに`{{ui:editor_context-menu_open-prefab}}`を表示します
- 入れ子が15階層より深くなる選択。何も書き込まれず、メッセージでそのことが伝えられます

## 配置をフラット化

配置をテンプレートから切り離します：配置のオブジェクトはふつうのレベルオブジェクトになり、今ある場所にそのまま残ります

場所：配置のインスペクター、ヒエラルキーの行のメニュー、コマンドパレットにある`{{ui:editor_inspector-prefab_flatten}}`

必ず先に確認を求めます。フラット化した後もレベルの見た目は変わらないので、確認がなければ、間違ったフラット化にはずっと後、テンプレートの編集が届かなくなったときに初めて気づくことになります。複数の配置を選択していれば、確認は1回、元に戻す操作も1回分です

配置が持ち込んだオブジェクトだけを単独でフラット化することはできません。それが属する配置をフラット化します

## 入れ子のプレハブもフラット化

フラット化するプレハブの中にあるプレハブがどうなるかを決めます

**オフ**：対象にした配置だけがテンプレートに従わなくなります。その中に配置されたプレハブは配置のままで、リンクを保ちます。その内側のテンプレートを編集すれば、引き続きレベルに反映されます。これがデフォルトです：「このプレハブを展開する」と言うとき、ふつう求められているのはこちらです。確認が開くたびにスイッチはオフになっています

**オン**：入れ子になったものもすべてフラット化されます。1回押した後は、どんな深さでも、レベル内の何もそれらの内側のテンプレートにリンクしていません

どちらの場合も、テンプレート自体はレベルに残ります。フラット化全体が元に戻す操作1回分です
