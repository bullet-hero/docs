# gv 0.16.2

Phones hold a steady 60 frames in levels and in the settings, and text input works with the on-screen keyboard

## Game

- A phone starts with anti-aliasing off, and a desktop stays on MSAA. With MSAA a Xiaomi 2209116AG loaded its GPU to 98% and gave 47-56 frames per second in a level. With FXAA instead the GPU was 51% busy, and the level held a steady 60. FXAA did not become the default either, because it keeps the post-processing pass on even in levels that have no post-processing. Anti-aliasing can still be turned on in the graphics settings, and switching from MSAA to another type now really turns it off
- A screen that covers the whole picture stops drawing the level behind it: the settings, the editor settings, generators and the beat window. On the same phone the settings run at 60 frames instead of 45. The level keeps playing under them, it is just not drawn
- The graphics settings show the framerate cap the game actually holds, for example `60 fps` or `Unlimited`
- Text input on a phone works with the on-screen keyboard. It opens every time a field is opened, its Done key saves the text and Cancel brings back the previous one, and the next field gets its own keyboard, so letters no longer end up in a number field. A grey inactive field can no longer be changed through the input window

## Editor

- A selected clip on the timeline gets a bright 4-pixel frame, and a selected keyframe point gets an outline. Before, the selection was a thin frame in a colour close to the clip's own frame, and on a phone it got lost
- In the editor on a phone the viewport leaves touches to you while a bot steers the avatar, so it can still be moved and selected in. Before, the viewport did not respond to any touch
- In the `Relative` control mode the cursor stays in its place on the screen while the camera moves. Before, it drifted across the screen
