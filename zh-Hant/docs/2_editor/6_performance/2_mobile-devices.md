# 移動裝置

在手機上，手指會遮住螢幕，邊緣被系統佔用。重要的內容要遠離邊緣，並在低配手機上測試關卡：最先拖垮它的是全屏半透明

手機和電腦一樣是目標平臺。只能在電腦上玩的關卡只完成了一半

## 用手指代替滑鼠

**手指會遮住螢幕**。滑鼠是一個點，手指是一塊下面什麼都看不見的區域。不要設計需要緊盯玩家所在位置的彈幕組合。這在電腦上可行，在手機上就是盲區

**操控方式不同**。在電腦上，游標設定目標，角色朝它移動。在手機上精度更低，手指的慣性也更大。用滑鼠一次就能通過的通道，在手機上會變成一道單獨的考驗

**讓狹窄的通道在時間上短暫**，而不是在寬度上狹窄

## 邊緣和螢幕形狀

> [!caution] 注意
> 邊緣屬於系統：攝像頭開孔、圓角、導航手勢。遊戲介面會避開不安全區域，關卡內容則不會。重要的內容要遠離邊緣，尤其是頂部邊緣

**寬高比**。手機大約是20:9，明顯比你工作用的螢幕更窄更長。在認定關卡完成之前，至少用裝置模擬器以這種形狀看一遍關卡

> [!caution] 注意
> 裝置模擬器能顯示比例和開孔，但完全不反映效能。在真實的低配裝置上跑一遍，勝過任何推理

## 最先拖垮手機的是什麼

按順序：
1. 多層疊加的全屏半透明
2. 後期處理，首先是泛光（Bloom）。它的開銷隨解析度增長，而不是隨物體數量增長
3. 大紋理。一張4096的圖片在繪製任何東西之前就佔用64MB記憶體。只有玩家自己的設定壓縮它時，才會降到四分之一
4. 粒子數量很多的特效
5. 最後才是形狀的數量

## 抗鋸齒

抗鋸齒是玩家的設定，不是關卡的設定。但它能解釋為什麼同一個關卡在兩部相近的手機上表現不同：
- `{{ui:enum_anti-aliasing-type_msaa}}`按取樣點計算。它的開銷隨半透明過度繪製增長，而這恰恰是低配手機本來就吃力的地方
- `{{ui:enum_anti-aliasing-type_fxaa}}`是對螢幕的一次處理，開銷與任何因素都無關
