# gv 0.13.2

Fixes for frames before an object's start, warm-up of level text, inactive objects on the timeline and the Escape key in editor windows

- An object with an anchored start plays earlier than its authored start, and on those frames it now holds its first keyframe. Before, the frame calculation threw an error there, which could stop the whole frame from being built, and in a release build could close the game
- Level text is prepared before the level starts again. After the text library was updated, the warm-up silently stopped working, and every letter went into the font atlas on the frame where it first appeared
- The Level and Prefab timelines show an object the level does not draw as a faded grey clip. That covers both an object with its active checkbox off and an object whose parent has it off. A prefab clip keeps a trace of its purple, so both states can be read
- `Escape` closes 22 editor windows the same way as a click on the background, among them unsaved changes, the search palette, backups, generators, the level password and the resource editors
- Level validation no longer reports a keyframe or object past the end of the level, and its fix no longer pins them to the last frame. Content past the end is allowed: it starts playing as soon as the level gets longer. A frame before the first one is still counted as a problem
