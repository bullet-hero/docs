# gv 0.13.3

Speicherverwaltung auf Handys - eine Grenze für den Rückgängig-Verlauf, eine Reaktion auf Warnungen bei wenig Speicher, ein geschlossenes Leck - und zwei Korrekturen im Prefab-Modus

- Eine neue Editoreinstellung, `Objekte im Verlauf`, begrenzt, wie viele Objekte der Rückgängig-Verlauf zusätzlich zu seiner Schrittzahl behält. Ein Massenlöschen ist ein Schritt, der 50 000 Objekte enthalten kann, und genau das fängt diese Grenze ab. Standardmäßig behält ein Handy bis zu 200 000, und ein Desktop hat keine Grenze. `0` hebt die Grenze auf
- Wenn Android oder iOS vor wenig Speicher warnt, reagiert das Spiel jetzt. Der Editor verwirft Zweige des Verlaufs, die nicht mehr erreichbar sind, und das Spiel gibt frei, was nichts mehr nutzt. Vorher hörte niemand auf die Warnung, und das einzige Ergebnis war, dass das System das Spiel schloss
- Bei jedem Öffnen eines Levels blieben zwei Materialien pro Textur bis zum Ende der Sitzung im Speicher. Jetzt werden sie freigegeben, wenn das Level geschlossen wird
- Das Schließen eines Levels im Editor gibt die Daten des Levels frei. Vorher blieben sie im Speicher, bis das nächste Level geöffnet wurde
- Nach einem schweren Level gibt das Spiel den dafür reservierten Speicher zurück, wenn es mehr als das Vierfache dessen ist, was ein übliches Level braucht, und das nächste Level ihn nicht braucht
- Die Prefab-Zeitleiste springt nicht mehr nach jeder Bearbeitung im Prefab-Modus zur obersten Zeile. Sie wird nur beim Betreten des Prefab-Modus zurückgesetzt
- Ein Objekt der obersten Ebene in einer Prefab-Vorlage ohne gesetztes Elternobjekt wird jetzt in die Zeitleiste der Vorlage eingepasst und folgt seinen Ankern, genau wie seine Kopien im Level. Vorher konnte ein Einfügen es außerhalb der Vorlage lassen, und der Editor zeigte es anders, als es abgespielt wurde
