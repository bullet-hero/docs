# 关卡文件夹与备份

关卡放在游戏文件夹内levels中自己的文件夹里。不要重命名它用到的文件，完整的备份就是关卡文件夹的副本

## 文件夹里有什么

关卡文件夹位于游戏文件夹内的`levels`中。游戏文件夹在哪里：[[1_installation]]

| 文件 | 是什么 |
|---|---|
| `level.json` | 关卡内容。二进制格式下为`level.blob` |
| `metadata.json` | 名称、描述、作者、标签。二进制格式下为`metadata.blob` |
| `logo.png`或`logo.jpg` | 封面 |
| 曲目、图片、字体 | 关卡用到的其他一切，直接放在`level.json`旁边 |

`levels`旁边是`resources`，里面是本设备的共享库：`themes`、`effects`、`shapes`、`prefabs`。它们不属于关卡。你把想复用的内容导出到这里，也从这里导入

同一个`resources`文件夹中还有`collections`，每个合集一个文件夹。更多：[[16_library-and-collections]]

发给别人的关卡自身包含所需的一切。共享库不会随关卡一起传递

## 哪些东西不要手动改

> [!caution] 注意
> 不要重命名关卡用到的文件。对它们的引用是按名称保存的，所以重命名的文件就是丢失的文件

关卡在游戏中打开时，不要用文本编辑器修改`level.json`。从编辑器保存会悄无声息地覆盖你的修改

不要在关卡文件夹中保留关卡用不到的东西。它们会随文件夹一起传递

文件格式由扩展名决定，而不是由文件内部的字段决定。所以在编辑器中更改格式时，会写入一个新文件并删除旧文件。否则磁盘上会同时有两个文件，无法判断哪一个才是真的

## 备份与恢复

**完整的备份就是关卡文件夹的副本**。它包含一切，包括资源。每次大改之前都复制一份，并标上日期

**自动保存只保存关卡文件**。不包括元数据、曲目和图片。每次自动保存都会把一份副本放进游戏文件夹中的`backups/<level id>/`，位于`levels`之外。保留`25`份副本。如何恢复副本：[[4_not-losing-work#自动保存]]

**打不开的`Json`关卡并没有丢失**。文件是文本，所以你可以用任何文本编辑器打开它，直接看着修复。游戏本身不会打开加载失败的关卡，所以`{{ui:settings_level-settings_raw}}`标签页在这里帮不上忙。它显示的是已经打开的关卡的模型

`Blob`无法这样挽救。它是二进制的，损坏的文件会被整个拒绝，而不是部分读取

在`{{ui:settings_level-settings_raw}}`标签页中编辑之前需要了解的内容：[[4_not-losing-work#原始数据标签页]]
