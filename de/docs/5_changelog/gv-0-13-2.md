# gv 0.13.2

Korrekturen für Frames vor dem Start eines Objekts, das Vorwärmen von Leveltext, inaktive Objekte auf der Zeitleiste und die Escape-Taste in Editorfenstern

- Ein Objekt mit verankertem Start spielt früher als sein festgelegter Start, und auf diesen Frames hält es jetzt seinen ersten Keyframe. Vorher warf die Frame-Berechnung dort einen Fehler, der den Aufbau des ganzen Frames stoppen und in einem Release-Build das Spiel schließen konnte
- Leveltext wird wieder vorbereitet, bevor das Level startet. Nach einem Update der Textbibliothek hörte das Vorwärmen still auf zu funktionieren, und jeder Buchstabe kam erst in dem Frame in den Schriftatlas, in dem er zum ersten Mal erschien
- Die Zeitleisten Level und Prefab zeigen ein Objekt, das das Level nicht zeichnet, als blassen grauen Clip. Das gilt sowohl für ein Objekt mit ausgeschaltetem Aktiv-Kontrollkästchen als auch für ein Objekt, dessen Elternobjekt es ausgeschaltet hat. Ein Prefab-Clip behält eine Spur seines Lilas, so lassen sich beide Zustände ablesen
- `Escape` schließt 22 Editorfenster genauso wie ein Klick auf den Hintergrund, darunter ungespeicherte Änderungen, die Suchpalette, Sicherungen, Generatoren, das Levelpasswort und die Ressourceneditoren
- Die Levelvalidierung meldet keinen Keyframe und kein Objekt hinter dem Ende des Levels mehr, und ihre Korrektur heftet sie nicht mehr an den letzten Frame. Inhalt hinter dem Ende ist erlaubt: Er beginnt zu spielen, sobald das Level länger wird. Ein Frame vor dem ersten zählt weiterhin als Problem
