# 画像とフォント

シェイプで済むならシェイプを使ってください：ファイルもメモリ消費も権利の問題もありません。画像は画面上の表示サイズに合わせ、モバイル向けレベルでは{{v:texture.mobile-max-side}}、全体でも{{v:texture.desktop-max-side}}を超えないようにします

画像のサイズは2のべき乗に切り上げてください

## フォーマットとサイズ

エンジンがファイルのバイト列からデコードできるものはすべて読み込めます。実際には`png`と`jpg`です

ファイルサイズにゲーム側の制限はなく、制限するのはハードウェアです：

| デバイス | 最大の辺 |
|---|---|
| Android（保証） | 4096 |
| Android（一般的） | 8192-16384 |
| デスクトップPC | 最大32768 |

## メモリ

**本当の制限はメモリです**。ファイルの容量にかかわらず、画像はメモリ上では生のピクセルとして保持されます。`png`は1ピクセルあたり4バイトです。`jpg`は透明度を持たないので3バイトです

| サイズ | メモリ（`png`） |
|---|---|
| 512×512 | 1MB |
| 1024×1024 | 4MB |
| 2048×2048 | 16MB |
| 4096×4096 | 64MB |
| 8192×8192 | 256MB |

> [!caution] 注意
> 8192のテクスチャは、画像1枚で4分の1ギガバイトです。スマートフォンでは遅いのではなく、クラッシュします

## プレイヤーが決めること

画像がどれだけメモリを使うかは、各プレイヤーのグラフィック設定の3項目で決まります：
- 読み込み時に画像を圧縮するか。圧縮すると上の数値が4-8分の1になります
- メモリ上の画像の最大の辺。辺が半分ならメモリは4分の1です
- ミップマップ（小さく描画するための縮小コピー）を作るか

スマートフォンは既定で画像を圧縮し、{{v:texture.mobile-max-side}}に制限します。デスクトップPCは画像をそのまま保持し、{{v:texture.desktop-max-side}}に制限します

**作者が担当するのは画像のフィールドで、まず何を描いた画像なのかです**。フィールドはリソース一覧で画像の隣にあります。縮小と圧縮に最も強いのは写真です。くっきりした輪郭の絵はそれより弱くなります

`{{ui:enum_texture-kind_pixel-art}}`は、デバイスの好みにかかわらずミップマップを持ちません。また最初は圧縮もスムージングもされず、これは`{{ui:level_resources_texture-compression}}`と`{{ui:level_resources_texture-sampling}}`のフィールドで変更できます

## ミップマップ

ミップマップは小さな画像のちらつきを防ぎます。画面上で小さく表示されている間、元の画像の代わりに描画される縮小コピーです。メモリが3分の1多く必要になります

ミップマップがないと、縮小した画像は滑らかにならず波打ちます。プレイヤーはミップマップをオフにでき、`{{ui:enum_texture-kind_pixel-art}}`は決してミップマップを持ちません

画面上で200ピクセルを占める4096の画像は、あらかじめ256に縮小した同じ画像の256倍のメモリを使います

## 画像よりシェイプ

シェイプはあらゆる面で画像より安上がりです：ファイルも、メモリも、権利の問題もありません。組み込みのシェイプは長方形に貼った画像ではなく、本物のジオメトリです。描画してから捨てられる透明な余白がありません

この差はスマートフォンで表れます。ミドルレンジのモバイルチップでは、1000オブジェクトのシーンでGPU時間の95-97%がピクセルのシェーディングに費やされます。シェイプが占めるのは自分の長方形の29.4%です。テクスチャ付きの四角形の残りは透明な無駄です

画像が必要なのは、まさに絵が必要なときです：ロゴ、写真、手描きのアート。幾何学的な形にはシェイプを使ってください。必要なものがなければ`{{ui:hint_level_shape-editor_header}}`で描きます

## フォント

フォントは`ttf`、`otf`、`ttc`で読み込まれます。独自のフォントがない場合、テキストはシステムにあるフォントで描画され、それはデバイスごとに異なります

`{{ui:settings_level-settings_fontcache}}`は、描画用にあらかじめ用意しておく文字のセットです。ジェネレーターがレベル内のテキストからこれを作り直します。テキストが変わらなくなったらジェネレーターを実行してください
