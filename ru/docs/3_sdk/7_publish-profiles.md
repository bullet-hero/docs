# Профили публикации

Как сервис заявляет, какие уровни он принимает, в виде файла данных, а не кода

## Профиль - это данные

Каждое место, куда может попасть уровень (Steam Workshop, официальный сервер, сервер сообщества, каталог магазинной сборки), по-своему отвечает на одни и те же несколько вопросов, и эти ответы меняются с годами, а код нет. Поэтому политика - это модель `PublishProfile`, которая сериализуется как любой другой корень со своим поколением. Добавить сервис - значит написать файл, а не править анализатор

Что решает профиль:

| Поле | Смысл |
|---|---|
| `ProfileKey` | какой это сервис, повторяется в каждом отчёте |
| `AllowedLicenses` | значения `TypicalLicenseType`, которые сервис принимает |
| `AllowedUriTypes` | как можно получать ресурсы. Пустой список значит любой способ |
| `AllowUnknownLicense`, `AllowPermissionInstead` | хватает ли неизвестной лицензии или письменного разрешения |
| `RequireResourceMeta`, `RequireResourceUrl`, `RequireAttribution`, `RequireAgeRating`, `RequireLevelAuthors`, `RequireHashes` | что обязано быть заполнено |
| `MaxResourceBytes`, `MaxDataFileBytes`, `MaxTotalBytes` | пределы размера, 0 значит без предела |
| `Sources`, `UnknownSourceTrust` | список сайтов и оценка для сайта, которого в нём нет |

Какие лицензии допустимы, живёт только в профиле. Это выглядит как свойство лицензии, но на деле это свойство принимающего сервиса

## Три встроенных профиля

| Фабрика | `ProfileKey` | Для чего |
|---|---|---|
| `CreateOpen()` | `local` | уровень на вашем устройстве. Ничего не требуется |
| `CreateStandard()` | `standard` | публичный сервер. Лицензии: CC0 1.0, CC BY 4.0 и 3.0, CC BY-NC 4.0 и 3.0, SIL OFL 1.1, MIT, Apache 2.0, the Unlicense. Ресурсы из папки уровня, из игры или по прямой ссылке. Пределы 64 МиБ на ресурс, 32 МиБ на файл данных и 256 МиБ на уровень |
| `CreateStrict()` | `strict` | магазинная сборка. `standard` плюс: без ссылок, обязательны атрибуция и хеши, пределы 32, 16 и 128 МиБ |

Лицензии семейства GPL исключены из `standard`, потому что GPL-работа, распространяемая через App Store, конфликтует с условиями Apple. CC BY-SA и CC BY-ND исключены, потому что ShareAlike заставил бы сменить лицензию самого уровня, а NoDerivatives запрещает редактирование, на котором построена игра. Строгие размеры - это то, что телефон может скачать по мобильной сети

> [!tip] Рекомендация
> Не добавляйте фабрику для своего сервиса. Возьмите один из трёх профилей, поменяйте нужные поля и поставляйте его JSON-файлом

## Откуда пришёл ресурс

Поле лицензии говорит, что заявляет автор. `SourceTrust` говорит, чего это заявление стоит с учётом сайта, откуда пришёл ресурс:

| Оценка | Исход | Примеры |
|---|---|---|
| `Approved` | публиковать | Kenney, ccMixter, Incompetech |
| `PartiallyApproved` | публиковать, запись стоит просмотреть | Pixabay, SoundImage |
| `RequiresLicenseCheck` | сверить лицензию с настоящей страницей | OpenGameArt, Free Music Archive, Wikimedia Commons |
| `RequiresResourceCheck` | сначала опознать саму работу | Rawpixel, itch.io |
| `NotAllowed` | отказать | YouTube, SoundCloud, Spotify |
| `Unknown` | записи нет, решает `UnknownSourceTrust` | - |

`TrustedSourceCatalog.CreateDefault()` возвращает 25 сайтов. Это стартовый список: предполагается, что каждый оператор его изменит, и ничто не вправе рассчитывать на наличие записи. Стриминговые платформы перечислены как `NotAllowed`, а не пропущены, потому что отсутствующий сайт оценивается через `UnknownSourceTrust`, а в `standard` и `strict` эта оценка просит проверки, а не отказывает. Пустой список `Sources` выключает оценку источников. Каталог и [UGC-LICENSING-POLICY.md](https://github.com/vertoker/bullet-hero-sdk/blob/master/Docs/UGC-LICENSING-POLICY.md) описывают одно и то же и правятся вместе

## Что вызывающий делает с ответом

У `PublishReadinessReport` есть `HasErrors` (находки группы `Error`), `NeedsManualReview` (`Warning`) и `IsReady`. Что делать дальше, профиль не решает: клиент блокирует загрузку при ошибках, сервер ставит уровень в очередь на проверку вместо публикации. Вызов - `ValidationFacade.ValidateForPublish`, см. [[6_validation]]. Та же проверка со стороны автора описана на [[5_publish-readiness]]
