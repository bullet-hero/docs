# 确定性

种子相同的关卡在任何设备、任何帧率下都以相同方式进行。其中的随机性由种子计算得出，你的操作不会影响关卡

## 关卡是时间的函数

关卡在时间轴上搭建。每个物体存在于一段帧的时段上，并沿关键帧移动

关卡不读取你的操作。所以不论你是活着、死了、正在冲刺还是由机器人代你游玩，第1200帧看起来都一样

影响是单向的。关卡可以改变化身的尺寸、让它减速、收回操控或关闭碰撞。不存在从化身到关卡的反向通道

没有触发器。未来的版本正在讨论它们，但还没有任何决定

关卡按现实时间运行。帧率只决定屏幕重绘的频率

同一局在每秒30帧和144帧下进行得完全一样

## 种子

种子取自第一个设置了它的地方：

1. 关卡画面上的`玩家种子`（`随机化`选择一个新的，`清除`将其移除）
2. 作者设置的关卡自己的种子
3. 为这一局生成的新种子

`0`表示“未设置”。所以普通关卡每次加载都会使用新的种子

结果窗口显示这一局的种子，记录也会保存它。这样就能重现一局幸运的游玩

## 随机性如何工作

关卡中的随机值不是来自一个记住自身状态的生成器。它根据自己的地址计算得出：

`Hash(seed, keyframe frame, layer, start frame, track, channel)`

同一个地址总是给出同一个数。在任何设备上，以任何计算顺序都是如此

地址的每个部分都是作者编辑的内容。所以相同的布局会重现相同的一局

## 这能带给你什么

- **Warm机器人**在一局开始前就规划好穿过整个关卡的路线。这之所以可行，是因为实际进行的正是它规划时所用的那个关卡
- **Reflex机器人**构建当前帧之后的帧，并据此闪避
- **倒回检查点**会重新构建所需的帧，而不是撤销任何东西
- **编辑器**从零构建任意一帧，所以拖动播放头是即时的
- **记录和统计**在任何设备上含义都相同

## 已知限制

关卡这一侧是确定的。化身这一侧有已知但尚未修复的缺陷：

- 两个障碍物在同一帧命中化身。由哪一个决定击退方向，在不同的局之间可能不同
- 化身的时钟在关卡开始时不会重置。根据关卡加载了多久，一次冲刺可能多持续或少持续一帧

在同一版本上重复同一局机器人游玩，实测结果精确到最后一位都一致。也就是说，这些缺陷不会在每个关卡上触发

因为它们，一局游玩在实践中可以重现，但不能保证
