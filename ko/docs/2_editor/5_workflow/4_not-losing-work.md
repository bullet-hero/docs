# 작업을 잃지 않기

작업은 자동 저장, 실행 취소, 레벨 폴더 사본이 지켜 줍니다. 레벨의 완전한 스냅숏은 폴더 사본뿐입니다. 파일 형식 변경과 레벨 삭제는 되돌릴 수 없습니다

각 안전장치는 다른 것이 다루지 못하는 부분을 맡습니다. 레벨 전체가 하나의 폴더이므로, 자동 저장과 실행 취소는 폴더 사본을 대신하지 못합니다

## 습관

> [!tip] 권장
> 섹션 하나를 끝낼 때마다 `Ctrl+S` 키. 구조를 바꾸기 전에는 매번 레벨 폴더 사본. 레벨이 완성되었다고 보기 전에 `{{ui:settings_level-settings_rules}}` 검사

## 자동 저장

자동 저장은 기본으로 켜져 있습니다. 동작은 다음과 같습니다:
1. 저장되지 않은 편집이 생깁니다 - `60`초 카운트다운이 시작됩니다
2. 게임이 레벨 사본을 게임 폴더 안, `levels` 바깥의 `backups/<level id>/`에 씁니다
3. 그다음 `Ctrl+S` 키를 누른 것처럼 레벨 자체를 저장합니다

변경 없이 연 에디터는 아무것도 쓰지 않습니다.
마지막 저장(직접 한 것이든 자동이든) 이후 바뀐 모든 것은 메모리에만 있습니다

사본은 `25`개까지 보관되며, 가장 오래된 것부터 삭제됩니다.
사본에는 레벨 파일만 들어 있고, 메타데이터, 트랙, 이미지는 없습니다. `{{ui:root_level-delete_backups}}`에 체크하지 않으면 레벨을 삭제해도 사본은 남습니다.
보호된 레벨의 사본은 그 레벨 자체의 비밀번호로 잠깁니다

켜기 여부, 간격, 사본 개수는 `{{ui:settings_common_title}}` → `{{ui:hint_settings_game-editor_header}}`에서 설정합니다

**복원:** 레벨 설정, `{{ui:settings_level-settings_dangerous-zone}}` 탭, `{{ui:level_backups_open}}`. 사본은 최신순으로 나열되며, 각각 만들어진 시점으로 이름이 붙습니다.
현재 파일은 먼저 `backups` 폴더 자체에 복사되므로, 복원도 되돌릴 수 있습니다

백업을 `level.json` 파일(또는 `level.blob` 파일)로 레벨 폴더에 복사해 직접 복원할 수도 있습니다

## 저장되지 않은 변경 사항

열린 레벨을 대체하거나 레벨을 떠나는 동작은 먼저 저장되지 않은 편집을 어떻게 할지 묻습니다:
- 레벨 목록에서 다른 레벨 열기, 레벨을 복사해 사본을 여는 것 포함
- 레벨 생성
- 에디터 설정과 레벨 설정의 `{{ui:settings_level-settings_quit}}`
- `{{ui:level_backups_open}}`
- `{{ui:settings_level-settings_dangerous-zone}}`에서: 레벨을 복사해 사본 열기, 파일 형식 변경, 비밀번호 설정

대화 상자에는 세 가지 답이 있습니다:
- `{{ui:editor_save_text}}` - 레벨을 저장하고 동작을 계속합니다
- `{{ui:editor_unsaved-changes_discard}}` - 빨간 버튼이며, 편집을 잃는 유일한 답입니다
- `{{ui:editor_cancel_text}}` - 아무것도 하지 않습니다

레벨 설정에서 플레이할 때도 묻지만, 답은 두 가지입니다: `{{ui:editor_unsaved-changes_save-play}}`, `{{ui:editor_cancel_text}}`. 게임에서 돌아오면 레벨을 디스크에서 다시 읽기 때문에 여기서는 편집을 버릴 수 없습니다.
저장되지 않은 것이 없으면 대화 상자는 나타나지 않습니다

## 실행 취소가 다루는 범위

실행 취소는 레벨 편집을, 오직 레벨 편집만 다룹니다. 오브젝트, 키프레임, 리소스, 테마, 프리팹, 설정에 대한 모든 변경은 하나의 작업 버퍼를 거칩니다

레벨을 바꾸지 않는 것은 실행 취소되지 않습니다:
- 선택한 기즈모, 타임라인 도구, 스냅과 그리드가 켜져 있는지 여부
- 패널 배치, 열린 탭, 재생 헤드 위치
- 클립보드
- 다시 생성된 세션 시드. 레벨을 다시 불러오면 새로 정해집니다
- **저장**. 실행 취소는 디스크의 파일이 아니라 메모리의 레벨을 되돌립니다

## 아예 되돌릴 수 없는 것

두 가지 동작은 디스크에 바로 씁니다:
- **레벨 파일 형식 변경.** 레벨을 `Blob` 형식으로 쓰면 이전 `Json` 파일이 삭제됩니다. 그리고 `Blob` 파일은 눈으로 읽거나 고칠 수 없습니다
- **레벨 삭제.** 그래서 `{{ui:settings_level-settings_dangerous-zone}}`에 숨겨져 있습니다

## 원시 데이터 탭

`{{ui:settings_level-settings_raw}}` 탭은 저장된 파일 전체를 필드 트리로 보여 줍니다. 아무것도 검사하지 않습니다: 규칙도, 제한도 없습니다

최후의 수단입니다. 한 세션의 모든 편집은 하나의 작업으로 적용되며, 실행 취소할 수 있습니다

> [!caution] 주의
> `{{ui:settings_level-settings_raw}}` 탭에 쓴 내용은 아무것도 검사하지 않았습니다. 레벨 폴더 사본을 가까이 두십시오. 자세히 - [[4_level-folder-and-backups#백업과 복구]]

## 규칙

실행할 만한 검사는 `{{ui:settings_level-settings_rules}}` 탭입니다. 검증이 찾아낸 문제를 보여 줍니다: 깨진 참조, 중복 ID, 부모 순환, 너무 깊이 중첩된 프리팹, 겹치는 비트 세그먼트

게임은 일부 문제를 수정할 수 있습니다: 하나씩, 또는 `{{ui:settings_level-settings_rules-fix-all}}` 버튼으로 한 번에.
수정은 `{{ui:editor_save_text}}` 버튼으로 적용되며, 실행 취소할 수 있는 하나의 작업입니다. `{{ui:settings_level-settings_raw-discard}}` 버튼은 수정을 버립니다.
그래프 문제에는 수정이 없습니다

자식의 구간이 부모를 넘어서는 것은 오류가 아닙니다. 정상적인 데이터이며, 의도대로 동작합니다.
수명을 맞추려면 `{{ui:mod_span_fit}}` 모디파이어를 실행하십시오
