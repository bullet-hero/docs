# 번역

번역은 자기 언어 폴더의 같은 경로에 둔 영어 파일의 사본으로, 텍스트만 번역한 것입니다. 어느 언어에 나타난 사실이든 다른 모든 언어로 옮겨집니다

## 미러링된 경로

모든 페이지는 모든 언어 폴더에서 같은 경로, 같은 파일 이름에 있습니다:

```
en/docs/2_editor/4_craft/3_difficulty-curve.md
ru/docs/2_editor/4_craft/3_difficulty-curve.md
zh/docs/2_editor/4_craft/3_difficulty-curve.md
ja/docs/2_editor/4_craft/3_difficulty-curve.md
ko/docs/2_editor/4_craft/3_difficulty-curve.md
es/docs/2_editor/4_craft/3_difficulty-curve.md
```

바뀌지 않는 것:

- 파일 이름과 모든 폴더 이름, 접두사 포함
- frontmatter의 `date`, `tags` (`title` 값은 번역합니다)
- `[[wiki-links]]`: 링크 대상은 파일 이름이며, 모든 언어에서 같습니다
- 외부 링크, 이미지 이름, 코드 블록, 인라인 코드: 파일, 필드, 키, 값, 명령
- 구조: 같은 순서의 같은 제목, 같은 목록, 표, 콜아웃

콜아웃 제목은 페이지의 언어로 번역합니다. 자세히 - [[style-guide]]

## 대체 언어는 영어

어떤 언어에 페이지가 없으면 사이트는 안내 문구와 함께 영어 페이지를 보여 줍니다. 반대는 성립하지 않습니다: `ru/`에만 있는 페이지는 영어 독자에게는 404 오류가 됩니다

> [!caution] 주의
> 페이지가 `en/`에 생기기 전에 다른 언어로 먼저 추가하지 마세요. 다른 모든 언어의 독자가 깨진 링크를 받게 됩니다

## 모든 언어가 모든 사실을 담습니다

영어는 주소에서만 기준이며, 내용에서는 기준이 아닙니다. 사실은 어느 언어에서든 먼저 나타날 수 있고, 그 뒤 다른 모든 언어로 옮겨집니다. 변경 후에는 모든 버전이 모든 버전에 있는 내용을 전부 담고 있어야 합니다

- **추가하되, 절대 지우지 않습니다.** 빠진 정보는 그 정보가 없는 모든 언어에 써 넣습니다
- **모순은 짐작으로 해결하지 않습니다.** 두 버전의 숫자가 다르거나 주장이 정반대입니까? 출처(게임, SDK)를 확인하고 pull request에서 문제를 제기하세요
- **묻지 않고는 아무것도 지우지 않습니다**, 오래되어 보이는 텍스트라도 마찬가지입니다

표현의 차이는 문제가 아닙니다. 독자가 알게 되는 내용의 차이가 문제입니다

## 버전 비교

저장소에는 Claude Code용 스킬이 있습니다: `compare-translations` (`.claude/skills/` 안). 이 스킬이 비교를 수행합니다. 스킬 없이 할 때는 같은 두 패스를 직접 진행하세요

**구조 패스**에서는 버전을 요소별로 비교합니다: frontmatter, H1, 첫 문단, 제목, 문단 수, 목록 항목, 표 행, 콜아웃, 링크 대상, 이미지, 코드

**의미 패스**에서는 각 섹션을 나란히 놓고 읽으며, 한 버전에는 있고 다른 버전에는 없는 사실을 찾습니다: 숫자와 단위, 필드, 버튼, 키의 이름, 조건과 예외, 경고, 절차의 단계와 순서, 예시

## 번체 중국어는 생성됩니다

`zh-Hant/` 폴더는 손으로 번역하지 않습니다. 스크립트가 `zh/` 폴더에서 변환합니다: OpenCC, 대만 어휘를 쓰는 번체자. 번체 중국어 페이지의 수정은 `zh/` 페이지에 하며, 다음 변환 때 옮겨집니다. `zh-Hant/` 폴더에서 직접 한 편집은 덮어써집니다

## 새 언어

새 언어는 전부 이 저장소에서 추가하며, 사이트 코드는 바뀌지 않습니다:

1. `frontend/en.yaml` 파일을 `frontend/<code>.yaml` 파일로 복사하고(예: `frontend/de.yaml`), 값을 번역합니다. 이것은 사이트 자체의 문자열입니다: 메뉴, 버튼, 검색, 쿠키 배너. 키와 모든 `{name}` 표기는 그대로 둡니다
2. `en/`, `ru/`, `zh/`, `zh-Hant/`, `ja/`, `ko/`, `es/` 옆에 `<code>/` 폴더를 만들고 그 안에 페이지를 번역해 넣습니다. 번역이 없는 페이지는 안내 문구와 함께 영어로 표시됩니다

`one` / `few` / `many` / `other` 형태를 가진 키는 개수에 따라 달라집니다. 해당 언어에 필요한 모든 형태를 넣으세요. 빠진 형태는 빌드가 알려 줍니다. 번역되지 않은 키는 영어로 표시됩니다. 빌드는 그런 키를 경고로 나열합니다

큰 번역을 시작하기 전에 [bullet-hero/docs](https://github.com/bullet-hero/docs)에 issue 하나를 열어, 두 사람이 같은 것을 번역하지 않도록 하세요
