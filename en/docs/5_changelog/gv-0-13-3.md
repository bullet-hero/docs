# gv 0.13.3

Memory handling on phones - a cap on the undo history, a response to low-memory warnings, a closed leak - and two Prefab Mode fixes

- A new editor setting, `History Objects`, limits how many objects the undo history keeps on top of its step count. One mass deletion is one step that can hold 50 000 objects, and that is exactly what this cap catches. By default a phone keeps up to 200 000, and a desktop has no cap. `0` removes the cap
- When Android or iOS warns about low memory, the game now responds. The editor drops history branches that can no longer be reached, and the game frees what nothing uses any more. Before, nobody listened to the warning, and the only outcome was the system closing the game
- Every time a level was opened, two materials per texture stayed in memory until the end of the session. Now they are freed when the level is closed
- Closing a level in the editor frees the level's data. Before, it stayed in memory until the next level was opened
- After a heavy level the game gives back the memory reserved for it, if that is more than four times what a usual level needs and the next level does not need it
- The Prefab timeline no longer jumps to the top row after every edit in Prefab Mode. It resets only when Prefab Mode is entered
- A top-level object in a prefab template with no parent set is now fitted to the template's timeline and follows its anchors, just like its copies in the level. Before, a paste could leave it outside the template, and the editor showed it differently from how it played
