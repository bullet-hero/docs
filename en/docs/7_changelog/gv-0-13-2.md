# Version 0.13.2

Fixes around frames before an object's own start, level text warm-up, inactive objects on the timeline and Escape in the editor's windows

- An object with an anchored start plays before its own authored start, and on those frames it now holds its first keyframe. Before, the frame math raised an error there that could stop the whole frame from being built, and in a release build could close the game
- Level text is prepared before the level plays again. After an update of the text library the warm-up had silently stopped working, so every letter was put into the font atlas on the frame where it first appeared
- The Level and Prefab timelines show an object the level does not draw as a washed-out grey clip. That covers an object whose own active checkbox is off and one whose parent's is off. A prefab clip keeps a trace of its violet, so both states stay readable
- `Escape` closes 22 editor windows the same way a click on the backdrop does, among them unsaved changes, the search palette, backups, generators, the level password and the resource editors
- Validation no longer reports a keyframe or an object placed past the level's end, and its fix no longer clamps them onto the last frame. Content past the end is legal: it plays as soon as the level grows. A frame before the first one is still reported
