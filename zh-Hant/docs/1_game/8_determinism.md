# 確定性

種子相同的關卡在任何裝置、任何幀率下都以相同方式進行。其中的隨機性由種子計算得出，你的操作不會影響關卡

## 關卡是時間的函式

關卡在時間軸上搭建。每個物體存在於一段幀的時段上，並沿關鍵幀移動

關卡不讀取你的操作。所以不論你是活著、死了、正在衝刺還是由機器人代你遊玩，第1200幀看起來都一樣

影響是單向的。關卡可以改變化身的尺寸、讓它減速、收回操控或關閉碰撞。不存在從化身到關卡的反向通道

沒有觸發器。未來的版本正在討論它們，但還沒有任何決定

關卡按現即時間執行。幀率只決定螢幕重繪的頻率

同一局在每秒30幀和144幀下進行得完全一樣

## 種子

種子取自第一個設定了它的地方：

1. 關卡畫面上的`{{ui:level_level-view_seed-value}}`（`{{ui:level_level-view_seed-randomize}}`選擇一個新的，`{{ui:level_level-view_seed-clear}}`將其移除）
2. 作者設定的關卡自己的種子
3. 為這一局生成的新種子

`0`表示“未設定”。所以普通關卡每次載入都會使用新的種子

結果視窗顯示這一局的種子，記錄也會儲存它。這樣就能重現一局幸運的遊玩

## 隨機性如何工作

關卡中的隨機值不是來自一個記住自身狀態的生成器。它根據自己的地址計算得出：

`Hash(seed, keyframe frame, layer, start frame, track, channel)`

同一個地址總是給出同一個數。在任何裝置上，以任何計算順序都是如此

地址的每個部分都是作者編輯的內容。所以相同的佈局會重現相同的一局

## 這能帶給你什麼

- **Warm機器人**在一局開始前就規劃好穿過整個關卡的路線。這之所以可行，是因為實際進行的正是它規劃時所用的那個關卡
- **Reflex機器人**構建當前幀之後的幀，並據此閃避
- **倒回檢查點**會重新構建所需的幀，而不是撤銷任何東西
- **編輯器**從零構建任意一幀，所以拖動播放頭是即時的
- **記錄和統計**在任何裝置上含義都相同

## 已知限制

關卡這一側是確定的。化身這一側有已知但尚未修復的缺陷：

- 兩個障礙物在同一幀命中化身。由哪一個決定擊退方向，在不同的局之間可能不同
- 化身的時鐘在關卡開始時不會重置。根據關卡載入了多久，一次衝刺可能多持續或少持續一幀

在同一版本上重複同一局機器人遊玩，實測結果精確到最後一位都一致。也就是說，這些缺陷不會在每個關卡上觸發

因為它們，一局遊玩在實踐中可以重現，但不能保證
